# 零售与百亿动态表单规约

更新日期 2026-11-25。草稿、提交、审核和详情按下文约定读写。存储字段见[数据字典](../sql/database-design.md)，商品目录见[商品方案](../architecture/catalog-admin-design.md)。

## 当前提交页面

申请人从「政策提交 → 提交政策」进入 `#/apply`，按基础信息、政策时间与详情、商品及补贴信息、其他信息填写。同一表单切换零售与百亿。商品读取 `goods` 在售目录。草稿保存、链接回填、正式提交和管理员审核已接入。申请页附件已接入上传、草稿绑定回填、提交快照和权限下载。

### 选商品与配置

在「商品及补贴信息」点「选择适用商品」，在同一抽屉切换选品方式。

| 方式 | 选择方式 | 加入政策后的填写方式 |
| --- | --- | --- |
| 「指定适用机型」 | 每次单选一件带具体颜色的在售商品，按商品 ID 防重复 | 每件商品独立成卡，显示具体颜色，隐藏标准 SKU。各平台数量选填，可留空 |
| 「选择手机型号」 | 按机型版本、RAM 和 ROM 选择整组在售商品，商品列表供核对 | 每次确认新建一张普通卡，本次所选商品共用该卡的适用平台和补贴。普通卡无数量输入 |

- 两种方式共用品牌、系列、机型、配置四级联动筛选，切换上级条件时清除已不匹配的下级值。商品列表为全宽单列，每行显示品牌、系列、机型、内存配置和颜色。
- 配置可多选，也可点「全部配置」选取当前品牌、系列和机型范围内的所有配置。普通卡按整组加入或移除，自动包含其全部在售商品。翻页或按颜色搜索只改变预览，组内商品只读。指定适用机型可用同一筛选，商品仍单选。
- 编辑已有普通卡时，取消配置同时将该配置的已有商品和本次新增商品移出勾选范围，包含列表其他页的颜色；仅在「保存配置」后更新原卡，取消抽屉保留原卡及补贴。已有部分选品的草稿或退回单保留原范围，申请人可按当前在售商品重选整组并保存；清空配置后移除最后一批商品仍须确认整卡移除。
- 商品卡按机型版本分行，显示「品牌 / 系列 / 型号」。普通卡的「适用配置」只显示容量，每个配置显示一次，移除标签会移除该配置下已选的商品。指定卡的颜色显示在独立的「颜色」字段。点击普通卡机型行最右侧的「编辑」后，选品抽屉回填该行的品牌、系列、机型和已有配置。申请人可整组增减配置或重选当前在售商品，点击「保存配置」后更新当前卡，保留已填的平台和补贴。取消编辑保留原选择。
- 同一申请内，每个机型版本、RAM 和 ROM 的组合只归入一张普通卡。该配置的全部在售商品使用同一张普通卡，各平台的补贴差异通过该卡的方案分配处理。其他普通卡的选品列表标记并禁选已占用的配置，「全部配置」也跳过这些配置。已保存的重复卡可打开整理，保存时校验配置归属。

### 平台与补贴

- 在「基础信息」选择整单平台。普通卡和指定适用机型卡默认沿用整单平台，整单新增平台时自动带入。卡片先显示当前适用范围，点击「调整平台」展开勾选并可缩小范围。自行调整的卡片不会自动接收后来新增的整单平台；「恢复整单平台」重新启用联动。
- 适用平台和补贴方案分别维护。新卡提供「方案 1」，选中的平台默认共用；添加其他方案后可为各平台单独分配。指定适用机型的数量独立填写，不随补贴方案共享。清除会丢失的表单内容前按页面确认流程处理。

### 确认政策适用范围

「调整政策时间」在独立弹窗中办理。在候选清单中可跨单号搜索勾选多张旧政策，点「添加所选政策」一次加入。可同时缩短和延长不同原单，每张分别填写新的北京时间截止时刻和必填原因，可上传证明文件，之后可继续添加或单独移除。点「核对调整」再弹出「确认政策时间调整」，列出每张单的原截止、新截止和原因。返回修改或关闭确认窗时，底层编辑窗保留已填内容和滚动位置。点「确认调整」后回到本次提交，重算下方交叉时段，保留确认依据未变的勾选。所选调整随本次申请整批通过或驳回。普通申请无交叉且未主动选择调整时直接送审。[适用范围和权限](../api/policy-api.md#整单提前结束)

申请人的确认窗口已移除顶部的通用说明和「平台」「判定结果」「商品或单号」三个筛选项。有命中时，窗口直接按平台列出机型版本和配置。普通商品默认显示命中颜色与件数，展开可查商品 ID。白色和黑色在同一时段命中相同旧单、补贴与分组结果时，一次确认即可。若银色命中另一份政策，同一配置卡内会标明银色对应的时段、单号与补贴。指定商品保留颜色和平台数量。窗口每页列出 10 张商品卡，翻页时保留此前的选择。底部显示整单确认进度，可返回编辑。所有决定齐全后，点「确认整单并提交」，再点「确认提交」送审。[分组确认示例](override-engine.md#6-决策表与验收案例)

有交叉时，申请人逐段确认实际采用的政策。服务端汇总本轮每个叠加段实际采用的所有政策，逐单将普通卡和指定卡勾选的具体商品跨平台合并去重。只有所有参与政策的商品 ID 集合完全一致，才进入运营初审。例如两单同选 Reno17 Pro 12GB+256GB，但其中一张多选一个颜色，即应整轮直接交采购。即便另一个叠加段内的两单完全相同，结论也相同。未选或仅单独采用的政策不计入比较。[审核阶段与办理结果](status-machine.md#状态迁移)

### 本地状态与提交边界

- 提交政策页的保存、提交、校验、读取失败、版本冲突、附件上传或下载错误，以及选品抽屉的加载和勾选错误，统一使用 Element Plus Message 弹出反馈。相同错误再次发生时可再次提示。接口成功后弹出「草稿保存成功」或提交成功信息。
- 申请单号、政策状态和文件进度作为普通页面信息展示。失败时保留重试、读取服务端版本等操作入口。

- 表单以北京时间维护起止时刻，精确到秒，请求携带 `+08:00`。填报截止字段为「到期时间」。首次生效从申请开始与采购批准中较晚的时刻算起，截止所在秒仍然有效。以后每次延期或提前结束都在同一政策上更新当前截止。清空日期范围同时清空两个时间值。金额保持十进制字符串。[日期与区间规则](override-engine.md#5-申请人后端区间试算)
- `ApplicantLayout.vue` 持有 `usePolicyForm`，区块通过事件表达修改意图，明细按稳定 key 更新。往返「我的提交」保留表单；退出、会话失效或账号、租户、角色变化时清除表单和暂存附件。已保存申请可通过 `#/apply?policyId=<id>` 刷新回填。
- 在当前工作台直接修改 `policyId`、从其他菜单返回另一份申请或通过浏览器前进后退切换申请时，同样先确认是否替换未保存内容。取消时恢复原路由并保留表单和暂存附件，不读取目标申请；确认后才加载目标内容。Hash 变化不得自动关闭该确认框。菜单返回当前申请、首次直达及保存后补写申请地址不重复确认。
- 附件选择后逐个上传，上传失败可重试，失败文件须重试或移除后再保存和提交。已保存文件随草稿回填，已提交文件保留在对应快照。点击「保存草稿」后以当前申请地址恢复本人草稿或驳回申请。点击「提交申请」先保存表单并预览。本单无交叉且未选择调整时直接送审，即使有可提前结束的其他旧单。独立调整旧政策时，从「我的提交」筛选栏打开「调整政策时间」。有交叉时在「确认政策适用范围」逐段选择后确认整单。服务端确认提交成功后弹出成功信息，回到不含 `policyId` 的 `#/apply` 页首，清空本次填写内容、商品卡及本地附件状态，恢复新申请初始默认值。提交响应异常但读取服务端确认本轮已成功提交时同样处理；提交失败或结果仍未确认时保留当前申请地址和输入。已提交政策及附件仍保留在服务端，可从「我的提交」查看。「我的提交」支持按状态、渠道和整单平台筛选，详情显示当前申请内容和驳回原因，不展示提交轮次或历轮审核入口；后台继续保留提交和审核日志。草稿和已驳回申请可继续编辑，待审及已通过申请可查看详情。本人未提交草稿可在「我的提交」确认后物理删除，成功后清除该草稿编辑缓存，附件仍按引用独立处理。打开其他申请前若有未保存内容，取消确认会保留当前表单和暂存附件。

前端检查及浏览器验收记录见 [前端规范](../architecture/frontend-development.md#9-验证记录与维护) 和 [整体架构](../architecture/system-overview.md#前端组件与页面现状)。

### 我的提交详情展示

「我的提交」列表每行保留「详情」。独立改期统一从筛选栏右侧的「调整政策时间」进入，可搜索单号，勾选一张或多张已通过的政策，同批分别延期或提前结束。逐单填写精确到秒的新截止和原因，证明文件选传。提前结束须负责原单至少一个实际使用平台，延期仅限本人提交且仍负责全部原平台。新增时段有交叉时逐段选择采用名单。核对后一次确认，整批直接通过，业务群按原单号收到调整说明。下次可再次选择同一张政策，以上次办理后的实际截止为准。[申请人接口](../api/policy-api.md#在原政策上改期)

- 申请人列表只展示申请单号、状态、渠道、整单平台、更新时间和操作，不展示提交轮次；详情直接展示当前申请内容，不设审核历史页签。对外短单号如 `ZC-000005`，由已有申请 ID 生成，重提时保持不变。后台保留日志、版本与原始快照。
- 已通过政策的详情分别显示「首次获批截止」和「当前截止」，每次已生效的延期或提前结束从新到旧列在「时间调整记录」。本次申请附带的其他原单改期另列在「本轮政策时间调整」。管理员从「差异化政策 → 查看」进入，可在「当前申请」和「审核记录」之间的独立「时间调整记录」页签查看该政策自身的改期历史。[管理员政策详情](../architecture/admin-workspace.md#差异化政策)
- 已驳回申请在「申请内容」顶部和「继续编辑」页顶部显示本轮退回环节、原因、实际审核人和时间，原因保留换行。页面只匹配本人当前提交轮次的 `REJECTED` 记录。初审退回须有原因，采购驳回可省略意见，无意见时提示「审核人未填写驳回原因」。本轮日志缺失或读取失败时提供重试。申请人可修改原单重提，历轮日志和快照继续保存在后台。[退回与原单重提](../architecture/policy-workflow-phase-c.md)
- 「申请内容」展示当前商品及补贴；待审核和已通过内容来自对应提交快照。每张原始商品卡保持独立，按机型版本分组，每个配置只列出实际勾选商品的颜色，避免重复完整商品名称。配置中的 `1024GB` 显示为 `1T`。
- 适用平台与补贴直接对应。共用方案的平台并排展示同一份补贴参数，不同方案分行。固定方式展示金额与上限，比例方式展示比例与计算基数，金额和比例保留接口返回的十进制字符串。
- 指定适用机型显示具体颜色及各平台独立数量，数量 `0` 与未填写分别显示。草稿未选方案、未分配平台或参数暂缺时按实际情况标注，不推定适用范围。
- 已提交内容仅使用对应快照的商品名称、颜色和补贴。草稿目录缺失或规格不匹配时显示商品 ID 和原配置，不借用当前目录中其他规格的名称、颜色。窄屏下配置和补贴分行排列。

## 渠道与平台

「平台」与「全部选择」只列入当前渠道分给本人的平台。零售、百亿的同名平台独立分配。同一人可以兼管两个渠道的拼多多，也可以只负责其中一个。尚未分配时页面提示联系管理员。重新编辑旧草稿时，页面列出已移交平台，申请人可移除并继续，所属渠道和历史单据按提交时的内容显示。「机型补贴查询」默认查询全部负责平台，可选单个渠道和平台组合，覆盖该范围内其他提交人已通过的政策及后续安排。[查询权限](../api/page-api-plan.md#申请人机型补贴查询)

申请人默认进入「提交政策」，侧栏「政策提交」下有「提交政策」「我的提交」「机型补贴查询」三个入口。渠道在同一张表单中选择。申请人与管理员共用顶部栏，提供侧栏开关、当前位置、当前角色已有菜单搜索、使用帮助和登录人信息。头像来自飞书登录资料，缺失或加载失败时显示姓名首字。菜单搜索返回提交页时使用当前申请地址，沿用未保存内容保护。

桌面和平板侧栏的「政策提交」可点击展开或收起，默认展开，箭头随展开状态变化，支持键盘操作。子菜单文字前不显示圆点。收起分组不切换页面，也不清理已填表单；手机保留顶部的提交政策、我的提交和机型补贴查询三个入口，不受桌面收起状态影响。

两种工作台侧栏共用 `workspace-navigation.css`，统一字体、品牌间距、蓝色分组、子菜单缩进、浅蓝选中态及展开箭头。桌面侧栏宽 196px，平板宽 160px；申请人侧栏底部不显示「申请人工作台 / APPLICANT」、蓝点和分隔线。管理员手机保留抽屉式菜单，申请人手机可从顶部导航直接切换页面。[实现与验证](../architecture/frontend-development.md#2026-11-15-共用顶部导航与飞书头像)

| 项目 | 零售 | 百亿 |
| --- | --- | --- |
| 渠道 | 零售渠道 | 百亿渠道 |
| 平台 | 快手、拼多多、京东、抖音、天猫、淘宝、招商、得物、联通、政企 | 拼多多、淘宝、联通 |
| 平台选择 | 单选、多选、全部 | 单选、多选、全部 |
| 核销类型 | 销售维度 / 激活维度，二选一 | 不适用 |
| 涉及场景 | 国补、地补、自补多选，默认国补；「全部」勾选三项，再点可清空。草稿允许未选，正式提交至少一项 | 不适用 |
| 预估政策 | 是 / 否 | 不适用 |

零售申请中，「涉及场景」的全部勾选项与「核销类型」共同确定这张政策所属的组。例如勾选国补和地补、选择销售维度，整张政策属于「国补＋地补／销售」组，补贴参数只取一次。提交时若与同平台、同商品的其他政策在时间上重叠，申请人在每段勾选要执行的单号。可以只选一张，也可以从多个组各选一张叠加。[逐段选单示例](override-engine.md#京东-reno17-pro-逐段选单示例)

保留“招商”等名称，不替换或合并。“全部”是操作，保存明确集合，不保存 `ALL`；未来新增平台是否适用历史全选政策待确认，不自动扩展。

渠道切换同步选项；百亿核销类型、场景、预估标记为 `NULL`。正式接入后由服务端拒绝跨渠道平台与字段。当前切换会清空平台和明细，已有平台时先提示确认；取消已填写平台也提示，数量 0 仍视作已填写。

## 后端持久化方案

草稿写入 `policy_apply.goods_form_json`，保存两类卡选中的商品 ID、卡片类型、平台联动、补贴方案及平台分配。审核和历史从 `policy_audit_log.snapshot_data` 回读本轮提交内容。普通卡数量为空，指定卡数量按平台选填。

指定卡的数量只作参考。留空保存为 NULL，填 0 按原值保存，两者均不改变商品适用范围。两类卡提交时均须传实际勾选的商品 ID，由服务端核验商品在售、配置归属并生成显示快照。

例如 12+256 在售黑、白两款，选择手机型号并选该配置就提交两款。只申报白色时，使用「指定适用机型」。同一申请的同一平台、商品只能出现一次。后续单独申报白色的另一张政策可以与整组原单按既有规则交叉或叠加。

同机型跨平台可使用不同补贴，也可部分或全部平台共享。共享方案展开时各平台保留各自的数量。

例如同一指定颜色商品，拼多多数量 100、固定补贴 50 元，淘宝数量留空、比例 10%，分别形成两条平台明细，淘宝数量保持为空。示例仅解释结构。

每轮提交从同一份表单按实际平台和选中商品生成 `policy_goods_detail`，每条保存轮次、平台、商品 ID 及所属机型版本、RAM、ROM。每条明细平台须属于整单平台，按平台和商品 ID 从该轮快照定位补贴及数量。

## 当前补贴互斥规则

| 方式 | 相关字段 | 必须清空 |
| --- | --- | --- |
| 固定 `FIXED` | 固定金额、补贴上限 | 比例、计算基数 |
| 比例 `RATIO` | 比例、计算基数 | 固定金额、补贴上限 |

每个补贴方案只填一种方式对应的字段，系统保存填写值供查阅。基数选项为零售价、政策价、到手价、地补实际、商家配控。切换清理另一组参数，前后端校验互斥。草稿允许当前方式字段暂缺。

金额按 `DECIMAL(10,2)` 的精度校验，比例按 `DECIMAL(5,2)` 百分数校验（10.00 表示 10%）。当前范围为填写、保存和展示补贴参数。

## 实单与待确认口径

历史实单包含同时记录比例和上限、以及仅记录上限的样本。当前提交按上表填写所选方式对应的字段。

## 主数据与附件

- 吉客云同步一加和 OPPO，先按 SKU 保存原文，再按受控规则识别系列、型号、配置和颜色。唯一明确且校验通过时自动创建或复用规格颜色，缺失、歧义和冲突由人工审核。新基线将已确认的配置和颜色写入 goods，来源保留候选并记录 goods_id。[自动清洗](catalog-cleaning.md)
- 空库 SQL 保存每轮商品 ID、机型、RAM、ROM 及完整提交快照。服务端核验商品状态和配置归属后生成快照，目录改名后已提交政策仍按该轮快照回读。
- 管理端已接入标准目录查询与维护，申请页读取同一套在售目录。实单只作为需求依据，不写入种子数据。吉客云维持只读。
- 支持特别备注、上传或链接。文件沿用本地 data 存储和 10 个、单文件 20MiB 的工程限制，下载按本人申请或有效管理员及提交轮次鉴权。必填与最终容量要求仍待确认，具体类型、链接规则和历史保护见[附件接口](../api/attachment-api.md)。
- 申请仅保留「特别备注」，前端 `remark` 映射 `policy_apply.remark`，移除「其他说明」输入、展示及 `other_desc` 数据列。链接及上传后的文件 ID 保存到 `attachment_urls`，元素规则见附件方案。

## 草稿与提交

草稿至少有服务端单号、申请人和渠道，可不选平台、不建明细；时间、机型和补贴字段可暂缺，已填写内容仍校验类型和互斥。

正式提交须有平台、起止时间及完整商品卡，校验实际选中的商品、配置归属、补贴方式和参数，并生成商品快照。零售分类字段必填。每个已选平台是否至少一条完整明细、固定上限是否必填、备注附件要求仍待确认。

点击「提交申请」先保存当前表单并读取整单预览。出现交叉时按平台、实际选品和时段展示旧单、补贴和各组结果，所有时段确认后提交。普通申请无交叉且未选择时间调整时直接送审。随单调整可在范围确认窗中办理，独立调整从「我的提交」筛选栏办理。返回编辑保留内容和附件。正式提交时，服务端复核在售商品、配置和字段完整性，按平台及最终所选商品写入明细和本轮快照。见 [状态机](status-machine.md) 和 [申请人接口](../api/policy-api.md)。
