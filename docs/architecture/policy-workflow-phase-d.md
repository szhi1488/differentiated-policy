# D 阶段工作台交付（P18–P22）

2026-11-23。申请人、产品运营和采购已可在 ERP 工作台完成两级审核。产品运营沿用本人账号和原有工作台，办理权来自当前轮的有效指派。目标环境沿用 B 阶段的数据库基线和按轮切换开关。[切换条件](policy-workflow-phase-b.md#切换与运行边界)

后续 E 阶段沿用本阶段的申请人选单页面和两级审核工作台。直接提交和确认整单的分流、逐人私聊审核卡及初审结果群通知统一在 [E 阶段设计](policy-workflow-feishu-technical-design.md#nodes)维护。

## 工作台入口

| 编号 | 入口 | 可以办理或核对的内容 |
| --- | --- | --- |
| P18 | 两种工作台的「待我审核」 `#/reviews` | 列表只列本人当前可办的指派。打开后可核对冻结的产品运营和采购成员、实际决定、逐段时段与商品、原执行和拟执行名单、本轮附件。初审同意后转采购，退回时原因必填。竞办冲突会重新读取原轮，保留已填写的意见，显示实际签署人和同组结办情况。 |
| P19 | 管理员「政策管理 → 差异化政策」 | 可用「审核阶段」筛选初审和终审，查看实际初审人与时间。知悉中的采购可阅读本轮依据，取得终审权的成员才可批准或驳回。历轮快照、原筛选条件及旧流程政策仍可查阅。[采购接口](../api/admin-api.md) |
| P20 | 申请人「我的提交」和「继续编辑」 | 待审申请显示当前阶段。驳回后从本轮日志显示退回环节、实际退回人、北京时间和原因。原申请人修改后以原单号重提，服务端按当时名单冻结新一轮。平台移交仍由原申请人修改自己的申请。[申请人接口](../api/policy-api.md) |
| P21 | 管理员「系统管理 → 政策审核设置」及「差异化政策 → 当前申请详情 → 改派本轮成员」 | 默认名单按姓名、部门查找，跨页按本地用户 ID 勾选两组人员。在途改派独立核对目标环节、完整名单及原因。保留者沿用原指派和待办，未来采购的待办在转入终审时登记。[设置与改派说明](../api/policy-review-settings.md) |
| P22 | 飞书中的站内办理链接 | 登录后按原单、原轮、原节点重新核权。当前可办者进入办理页，同组已办及历史轮显示实际结果。退回修改链接只对原申请人本轮仍被驳回的申请打开表单。 |

## 办理链接约定

以下示例使用同一张申请。链接由站点原点加 Hash 路径组成，单据 ID 是十进制字符串。

| 用途 | 路径示例 |
| --- | --- |
| 查看第 2 轮 | `/#/reviews/57?round=2` |
| 第 2 轮产品运营初审 | `/#/reviews/57?round=2&node=PRODUCT_REVIEW` |
| 第 2 轮采购终审 | `/#/reviews/57?round=2&node=PURCHASE_REVIEW` |
| 原申请人修改第 2 轮退回的原单 | `/#/reviews/57?round=2&node=REVISION` |

审核页将 `round` 传给按轮详情及下载接口的 `submissionVersion`。指定节点已结束时，该链接只读。原申请人修改页保留 `#/apply?policyId=57&round=2`，通过本人申请接口重新读取版本和状态后才展示表单。切换目标前沿用未保存确认，取消后保留原地址、输入和附件。

客户端免登保留当前 Hash。普通浏览器的扫码和网页授权共用固定的站点根回调，标签页只保存这次 OAuth state 对应的站内办理路径。回调清除授权参数并一次性恢复目标；工作台等服务端确认身份后才挂载。回跳解析校验单据、轮次和节点，拒绝重复或额外参数。授权范围由服务端按本轮重新计算。[飞书登录流程](feishu-auth-flow.md)

## 本地验收

- **贯通办理。** Chrome 加载生产前端，连接真实 Spring Boot HTTP 接口与隔离 H2，飞书身份由本地测试替身提供。管理员在设置页为两组各选两人并保存，在途改派后核对保留人员的指派 ID。第一名运营从页面退回叠加申请，原申请人从修改链接回填，核对叠加选单并以原单号重提。第二名运营按新名单同意，采购从现有详情批准。首轮和新轮分别保存，实际签署人依次为测试用户 2、3、4；同组另一采购显示「同组他人已处理」。[后端贯通回归](../../backend/src/test/java/com/company/policy/service/PolicyReviewSubmissionIntegrationTest.java)
- **页面与登录。** 在 1440×1000、768×1000、390×844 的 Chrome 生产预览中，以模拟会话和接口验证两种工作台、按轮详情、采购筛选、退回编辑、默认名单跨页选择及在途改派。另用模拟飞书网页授权、扫码回调和客户端免登实际走浏览器跳转，核对原单原轮、历史轮只读及链接转发后的无权状态。[路由测试](../../frontend/tests/integration/router.test.js) · [会话测试](../../frontend/tests/integration/App.test.js) · [退回修改与未保存保护](../../frontend/tests/integration/ApplicantLayout.test.js)
- **并发和未保存内容。** 采购从过期列表点击「审核」，或在旧轮驳回窗打开期间连续切回窗口，均须从最新列表重新打开才能办理新轮。旧窗不会提交原意见。申请人修改链接首次读取失败后重试，同版本继续保留已填备注及暂存附件；服务端版本发生变化时须确认替换输入。[采购回归](../../frontend/tests/components/AdminPolicyApproval.test.js) · [申请表联动回归](../../frontend/tests/integration/ApplicantLayout.test.js)
- **工程检查。** 前端 `npm.cmd run check` 通过 ESLint、Prettier、40 个文件的 277 项测试和 Vite 生产构建。后端 Maven `verify` 完成打包及 Spotless 检查，309 项中 307 项通过，真实 MySQL 登录和吉客云商品实查按配置跳过。

目标 MySQL 的升级、执行计划与并发行锁仍待在目标环境核对。真实飞书手机登录、群点名、待办投递及回执待后续阶段联调。本站内验收使用本地隔离数据。
