# 前端架构与开发规范

更新于 2026-11-24。本文维护 `frontend/` 的技术设计、整改清单和验收标准。项目级协作指令见 [AGENTS.md](../../AGENTS.md)。

## 1. 适用边界与阅读顺序

先读 [文档总览](../README.md)、[整体架构](system-overview.md)，再读本文件和当前模块业务/API 文档。申请表单对应 [动态表单](../business/perspective-rules.md)与[政策接口](../api/policy-api.md)，管理员页面对应 [管理员工作台](admin-workspace.md)，身份流程对应 [飞书鉴权](feishu-auth-flow.md)。

- 2026-11-11 已实施数据边界、页面与样式、基础状态三个阶段的适用整改，具体证据见本文件第 9 节。阶段四已接入管理员商品业务，政策流程仍按对应文档推进。当前结构见整体架构。
- 保留 Vue 3、Vite、JavaScript、Composition API（`<script setup>`）、Vue Router Hash 路由和 Element Plus；保持组件/样式按需导入、中文语言包、工作台及子页延迟加载。
- 不以全量 TypeScript 迁移作为整理前置条件；核心表单、DTO、响应模型通过 JSDoc 说明类型与空值语义。复杂跨页面共享出现前，不强制引入 Pinia；会话入口必须唯一。
- 不另设与现有分层并行的 `modules/features/services` 体系，不因重构引入第二套 UI 库、Tailwind 或重复请求库。新增依赖需说明必要性、体积和维护影响并同步 lockfile。
- 保留客户端免登和普通浏览器网页 OAuth，不能改变固定 Origin 首页回调、参数先清理再请求、服务端校验 state 和 Cookie 会话等边界。
- 管理员源商品库、商品清洗和商品中心已接入后端。商品中心的列表、详情、统计、手工新增、编辑、删除及数据字典维护见[管理员工作台](admin-workspace.md#商品中心)。申请页已接入真实在售选品、平台及补贴方案、草稿保存回填和正式提交。「我的提交」已接入本人分页列表、当前详情及驳回原因，申请人界面不显示提交轮次、历轮审核或快照入口。
- 管理员「差异化政策」的查看与审核共用 `AdminPolicyDetail.vue`。当前申请或历史快照读成功后立即显示商品、补贴和附件。本轮成员单独读取，失败时在成员区显示原因并可重试。列表的「审核」和飞书采购链接需同时核对服务端 `reviewable`、单号、提交轮次、记录版本、采购阶段和本人的办理权限，才显示通过与驳回。驳回原因在独立小窗填写。[差异化政策](admin-workspace.md#差异化政策)
- 管理员「机型补贴查询」读取标准目录与已通过政策历史，ECharts 6.1.0 按需加载。两图、指针和明细复用一次接口响应，重试、空结果及权限错误沿用管理员请求层。[查询页面](admin-workspace.md#机型补贴查询)
- 金额舍入、上限细则及附件最终约束等未定事项由对应业务文档跟踪。

## 3. 目录与依赖方向

沿用现有顶层分层，并在复杂业务内部归组。下列为目标骨架，不要求提前创建全部目录或空壳文件；现有文件迁移时同步 import、测试和文档。

  App.vue                         中文配置和应用内容出口
  router/

    routes.js                     路由名称、记录、角色元信息
  layouts/
    AdminLayout.vue               管理员导航、身份区、页面出口

  api/

    feishu.js                     现有认证 API
    attachments.js                现有独立附件 API
    policies.js                   申请人政策 API，按业务接入建立
    admin-policies.js             管理员政策列表、详情及审核 API
    catalog.js                    目录/商品 API，按业务接入建立
  constants/

    policy/

    catalog/                      商品模型转换
    feishu/                       SDK、授权和错误适配
  components/                     跨业务通用组件，如图标、品牌标识

    auth/FeishuLoginPage.vue       客户端免登、浏览器扫码与网页授权

| 层            | 职责与允许依赖                                    | 禁止事项                                               |
| ------------- | ------------------------------------------------- | ------------------------------------------------------ |
| views/layouts | 页面组织、路由参数、组合状态和业务组件            | 直接 fetch、复制纯规则、计算最终权限或生效             |
| components    | props/model 输入，emit 修改意图，维护自身显示状态 | 偷改父级对象、伪造业务事实、混入演示数据               |
| composables   | 维护状态、协调动作和 API，调用纯规则/适配器       | 导入 views、在多个位置维护同一规则或身份副本           |
| utils         | 纯转换/校验；外部 SDK 适配单独命名并明确副作用    | 纯工具弹窗、导航、持有页面状态；伪装成纯函数的网络请求 |
| api           | 路径、方法、参数、统一 request 调用               | 弹成功通知、改页面状态、判断审核结果                   |
| constants     | 稳定编码、固定显示映射                            | 业务查询、会话、可变表单数据                           |

Vue 文件用 PascalCase，composable 用 `useXxx`，动作以业务动词命名。选中对象按实体命名，例如 `selectedPolicyId`、`selectedSourceId`，避免一个泛型 selected 混合不同实体。约 300 行开始检查职责，约 400 行以上说明保留原因；这是审查参考，不是机械拆分或新增检查脚本的硬阈值。

## 4. 组件和状态设计

1. 一个路由页面围绕一个主要业务任务组织；独立数据源、筛选分页、实体详情属于拆分信号。申请表单按基础信息、时间、机型及补贴、附件等业务区块组织。
2. 先使用 Element Plus；只在项目统一语义、重复交互或稳定复用出现时封装。避免仅改名透传的包装组件和庞大的万能表单/表格配置引擎。
3. 父级拥有业务状态。明细子组件用 `update-detail`、`remove-detail`、`change-subsidy-mode` 等事件表达意图，携带稳定行 key；状态层集中执行修改。禁止通过 props/model 的嵌套引用静默改写父级业务对象。简单标量或整值替换的 v-model 可以保留。
4. 渠道清理、平台取消、补贴互斥、规格清空颜色、共享补贴展开各有唯一实现入口。共享只展开补贴参数，不复制平台数量；列表使用服务端 ID 或创建时固定的本地 key。
5. 清除渠道、平台、表单内容等待确认完成后再变更；取消保留原值。异步确认期间避免重复进入或应用过期动作。
6. 跨菜单保留表单是现有体验，迁移路由不能破坏。表单状态可提升到申请布局生命周期；浏览器刷新恢复是独立能力，未实现前不承诺。缓存按用户隔离，退出或身份变化清理，不能默认把表单和附件写入 localStorage。
7. 会话唯一入口负责用户、初始化、登录、退出、失效及重置；router 只读取它。不在模块导入时发起网络请求，入口需支持独立测试和重置。非会话业务状态默认归所属页面/布局。

## 5. 业务模型、校验与接口适配

### 模型与编码

- 渠道、平台、状态、补贴方式和颜色范围用稳定编码；中文只负责显示，映射维护一处。`ALL` 只能是界面操作，保存明确平台集合。
- 表单编辑模型、API DTO、详情展示模型分开定义。API 字段以实际 DTO/VO 和对应契约为准；草案变化同步文档，不为迁就页面私自改变服务端契约。
- 提交经字段白名单适配，禁止 `JSON.stringify(form)` 直接发送。当前 `channel/platforms/scenes/mode/priceBase` 与契约 `perspective/selectedPlatforms/sceneTypes/subsidyMode/basePriceType` 需要显式映射；详情反向回填也经过适配。
- `remark/links` 依次映射为特别备注及外部链接项，上传绑定按附件契约实施。身份、租户、操作者、审核结果及名称快照由服务端确定。

### 精度、时间与空值

| 数据      | 约定                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| BIGINT ID | 字符串，不用 Number 转换或做数值运算                                                                                                                   |
| 金额/比例 | 十进制字符串；禁止 Number、parseFloat、一元加号或浮点计算改变精度，不擅自舍入                                                                          |
| 数量      | 指定卡按平台选填参考数量，空字符串提交为 null，填 0 保存为 0，两者均不改变政策适用范围                                                                    |
| 布尔      | 区分 false、null 和未填写，false 显示“否”；禁止普遍用逻辑或运算符将假值兜底成“不适用”                                                                  |
| 时间      | 页面维护 `YYYY-MM-DDTHH:mm:ss` 北京时间墙上时间；政策接口若采用草案的 +08:00，由统一适配器显式转换，不用 toISOString 意外转 UTC；认证 Instant 单独处理 |
| 颜色      | 普通卡和指定卡正式提交都传实际选中的商品 ID，颜色名称由服务端生成快照                                 |

### 校验与目录

草稿和正式提交使用两套完整性策略，共享已填字段的格式、精度、互斥和归属前置校验。required 标记只表示界面提示，需配合实际规则与错误定位。前端校验改善体验，服务端仍做最终验证。不得擅自增加每个平台必须有明细、固定上限必填、备注附件必填等未确认门槛。

标准配置以 `spuId + ram + rom` 表示。两种卡都保留所选在售商品的 `goodsId`，名称用于展示和服务端快照。颜色仅取所属规格有效集合，切换规格清空旧颜色；商品已删除或数据变化时按真实错误处理。不同型号配置独立维护颜色，不用自由文本替代正式标准目录。切到固定方式时清除比例和基数，切到比例方式时清除固定金额和上限。百亿的零售专属字段为 null。

## 6. 路由、请求与业务操作

### 路由和权限

- 申请人表单、我的提交建立明确路由。管理员「商品」折叠菜单包含源商品库、商品清洗与识别和商品中心，默认进入源商品库。菜单引用路由名称，路由元信息声明页面准入，菜单不能充当全部路由规则。
- 产品运营在飞书私聊卡上处理需要确认的申请。卡内 `#/reviews/{id}?round=N` 只读，采购待办通过 `#/admin/policies?policyId={id}&round=N` 定位管理员「差异化政策」，退回后原申请人通过 `#/apply?policyId={id}&round=N` 修改原单。产品运营和管理员的菜单均已移除「待我审核」。采购终审权按本轮阶段、实际指派和当前资格核验。[办理链接约定](policy-workflow-phase-d.md#办理链接约定)
- query 按白名单解析类型、枚举和默认值，监听同路径参数变化。仅放允许分享的筛选条件、页码、记录 ID，不放凭证、敏感信息或未保存表单。详情 ID 存在性与访问权仍由服务端核验。
- 前端不能从 query、localStorage 或组件开关获得管理员角色。会话过期统一进入登录状态，保护未提交内容的处理不得绕过用户隔离或泄露数据。
- 客户端免登、浏览器扫码和网页授权遵循鉴权文档。`useAuthSession` 维护唯一会话，`useFeishuQrLogin` 管理二维码加载、刷新与释放。普通浏览器只在用户选择扫码时加载二维码 SDK。授权失败时重新发起，用户 token 由服务端处理。[飞书鉴权](feishu-auth-flow.md)

### 请求与列表

- 所有业务 API 通过 `api/request.js`。统一保留 HTTP status、稳定业务 code 和安全提示，区分网络、超时、主动取消、响应解析和业务失败。错误响应非 JSON 或为空时也不能丢失原 HTTP 状态。
- 支持调用方 AbortSignal，组合内部超时与调用方取消，结束后清理定时器/监听器；主动取消不显示“服务异常”。由页面决定业务提示，避免请求层和页面重复通知。
- 首次会话探测的 401 表示未登录；业务请求 401 触发统一会话失效；403 解释无权限；409 保留编辑内容并提示刷新核对，不静默覆盖。
- 列表区分 loading、error、empty、success；新查询取消旧请求或丢弃过期响应，卸载后不继续更新页面。筛选/页容量变化重置或校正页码，筛选字段明确，不用 Object.values 全对象拼接充当正式搜索契约。
- 政策、来源商品和日志接入后使用服务端分页与筛选，不加载全库到浏览器。总数、状态计数以相应接口定义为准。

### 写操作与真实结果

- 保存、提交、审核、任务控制期间防重复，携带服务端要求的版本；创建/提交结果不明时不盲重试 POST，按接口幂等方案或查询结果处理。
- 保存与提交若是独立接口，明确先保存再提交的顺序；不能让用户以为 submit 会自动包含未保存编辑。成功提示只在对应真实响应成功后出现。
- 业务页面使用真实 API。测试数据在 `frontend/tests/fixtures` 中维护。服务端失败时显示实际错误并支持重试。
- 正式详情组件不合成审核历史、同步结果或覆盖结论。演示历史也应在 fixture 中明确给出；缺真实历史显示空状态/错误，审核通过不等于当前生效。
- 文件上传状态与政策保存状态分别反馈。当前沿用本地存储、单文件 20MiB/最多 10 个的工程限制，最终业务容量待确认。上传失败保留文件供重试，阻止缺失附件的保存与提交；账号切换丢弃迟到响应。草稿保存后回填文件引用，历史文件按申请和轮次下载并保护物理删除。

## 7. 样式、响应式与可访问性

该版前端全量检查通过 37 个文件的 205 项测试及生产构建，历史组件回归覆盖当时的筛选后部分确认、同色不同 ID、时段和旧补贴差异、指定商品及缺少机型资料。用该构建和模拟申请人接口在 Chrome 1440×1000、768×1000、390×844 分别完成零售、百亿和无命中直提。零售三色同配置展示一张卡，两个时段合计三项选择回传六条原始决定，结果变化时重新确认。三个尺寸均核对直达、列表往返、展开商品、弹窗边界和提交，手机视口使用触控输入。

### 零售按完整场景组合逐段勾选政策

同一商品和平台的每个交叉段按完整场景集合及核销类型列出政策。申请人可换选同组政策，也可取消整组。每段至少勾一张，勾多组时显示实际叠加的单号。操作某组会保留其他组各商品的选择。

用京东 Reno17 Pro 12GB+256GB 三色的模拟数据核对了页面和提交请求。11 月 23–24 日先选 007＋003，再在国补组改选 006，综合组的 007 继续勾选。11 月 25 日单选 003。两段确认后提交六条商品及时段决定，三个颜色均分别回传 006＋007 和 003。[模拟验收截图](../business/images/retail-policy-selection.png) · [两段的全部选法](../business/override-engine.md#京东-reno17-pro-逐段选单示例)

本轮前端检查通过 37 个文件的 212 项测试及生产构建。生产构建配模拟接口在 Chrome 的 1440×1000、768×1000、390×844 三个视口验证了零售逐段选择、百亿和无命中直提，并核对变更后重选、提交的商品和单号。后端 Maven 验证共 225 项，223 项通过、2 项外部测试跳过。隔离 H2 接口测试覆盖提交、审核及按时点查询，另以旧版快照验证历史结果与待审复核。目标 MySQL 与真实飞书客户端待联调。[业务案例](../business/override-engine.md#6-决策表与验收案例)
