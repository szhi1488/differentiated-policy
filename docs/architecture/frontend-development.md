- 保留 Vue 3、Vite、JavaScript、Composition API（`<script setup>`）、Vue Router Hash 路由和 Element Plus；保持组件/样式按需导入、中文语言包、工作台及子页延迟加载。

- 保留客户端免登和普通浏览器网页 OAuth，不能改变固定 Origin 首页回调、参数先清理再请求、服务端校验 state 和 Cookie 会话等边界。

沿用现有顶层分层，并在复杂业务内部归组。下列为目标骨架，不要求提前创建全部目录或空壳文件；现有文件迁移时同步 import、测试和文档。

  components/                     跨业务通用组件，如图标、品牌标识

| 层            | 职责与允许依赖                                    | 禁止事项                                               |
| ------------- | ------------------------------------------------- | ------------------------------------------------------ |
| views/layouts | 页面组织、路由参数、组合状态和业务组件            | 直接 fetch、复制纯规则、计算最终权限或生效             |
| components    | props/model 输入，emit 修改意图，维护自身显示状态 | 偷改父级对象、伪造业务事实、混入演示数据               |
| composables   | 维护状态、协调动作和 API，调用纯规则/适配器       | 导入 views、在多个位置维护同一规则或身份副本           |
| utils         | 纯转换/校验；外部 SDK 适配单独命名并明确副作用    | 纯工具弹窗、导航、持有页面状态；伪装成纯函数的网络请求 |
| api           | 路径、方法、参数、统一 request 调用               | 弹成功通知、改页面状态、判断审核结果                   |
| constants     | 稳定编码、固定显示映射                            | 业务查询、会话、可变表单数据                           |

Vue 文件用 PascalCase，composable 用 `useXxx`，动作以业务动词命名。选中对象按实体命名，例如 `selectedPolicyId`、`selectedSourceId`，避免一个泛型 selected 混合不同实体。约 300 行开始检查职责，约 400 行以上说明保留原因；这是审查参考，不是机械拆分或新增检查脚本的硬阈值。

## 4. 组件和状态设计

1. 一个路由页面围绕一个主要业务任务组织；独立数据源、筛选分页、实体详情属于拆分信号。表单按基础信息、逐平台明细、附件等稳定业务区块组织。
2. 先使用 Element Plus；只在项目统一语义、重复交互或稳定复用出现时封装。避免仅改名透传的包装组件和庞大的万能表单/表格配置引擎。
3. 父级拥有业务状态。明细子组件用 `update-detail`、`remove-detail`、`change-subsidy-mode` 等事件表达意图，携带稳定行 key；状态层集中执行修改。禁止通过 props/model 的嵌套引用静默改写父级业务对象。简单标量或整值替换的 v-model 可以保留。
4. 渠道清理、平台取消、补贴互斥、规格清空颜色、共享补贴展开各有唯一实现入口。共享只展开补贴参数，不复制平台数量；列表使用服务端 ID 或创建时固定的本地 key。
5. 清除渠道、平台、表单内容等待确认完成后再变更；取消保留原值。异步确认期间避免重复进入或应用过期动作。
6. 跨菜单保留表单是现有体验，迁移路由不能破坏。表单状态可提升到申请布局生命周期；浏览器刷新恢复是独立能力，未实现前不承诺。缓存按用户隔离，退出或身份变化清理，不能默认把表单和附件写入 localStorage。
7. 会话唯一入口负责用户、初始化、登录、退出、失效及重置；router 只读取它。不在模块导入时发起网络请求，入口需支持独立测试和重置。非会话业务状态默认归所属页面/布局。

## 5. 业务模型、校验与接口适配

### 模型与编码

- 渠道、平台、状态、补贴方式和颜色范围用稳定编码；中文只负责显示，映射维护一处。`ALL` 只能是界面操作，保存明确平台集合。
- 表单编辑模型、API DTO、详情展示模型分开定义。API 字段以实际 DTO/VO 和对应契约为准；草案变化同步文档，不为迁就页面私自改变服务端契约。
- 提交经字段白名单适配，禁止 `JSON.stringify(form)` 直接发送。当前 `channel/platforms/scene/mode/priceBase` 与契约 `perspective/selectedPlatforms/sceneType/subsidyMode/basePriceType` 需要显式映射；详情反向回填也经过适配。
- `remark/explanation/links` 到备注与附件结构的无损映射未定，不能丢弃说明/链接或自行合并为后端未知字段。身份、租户、操作者、审核结果及名称快照由服务端确定。

### 精度、时间与空值

| 数据      | 约定                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| BIGINT ID | 字符串，不用 Number 转换或做数值运算                                                                                                                   |
| 金额/比例 | 十进制字符串；禁止 Number、parseFloat、一元加号或浮点计算改变精度，不擅自舍入                                                                          |
| 数量      | 编辑态可为空字符串，出站按契约转换为 null 或合法整数；不自动补 0，零值业务含义待确认                                                                   |
| 布尔      | 区分 false、null 和未填写，false 显示“否”；禁止普遍用逻辑或运算符将假值兜底成“不适用”                                                                  |
| 时间      | 页面维护 `YYYY-MM-DDTHH:mm:ss` 北京时间墙上时间；政策接口若采用草案的 +08:00，由统一适配器显式转换，不用 toISOString 意外转 UTC；认证 Instant 单独处理 |
| 颜色      | ALL_COLORS 的商品 ID 和颜色快照为 null。SPECIFIC_COLOR 正式提交必须有当前配置的有效商品。null 范围表示草稿未选                                 |

### 校验与目录

草稿和正式提交使用两套完整性策略，共享已填字段的格式、精度、互斥和归属前置校验。required 标记只表示界面提示，需配合实际规则与错误定位。前端校验改善体验，服务端仍做最终验证。不得擅自增加每个平台必须有明细、固定上限必填、备注附件必填等未确认门槛。

标准配置以 `spuId + ram + rom` 表示，指定颜色用该配置的 `goodsId`，名称用于展示和服务端快照。颜色仅取所属规格有效集合，切换规格清空旧颜色；停用或数据变化按真实错误处理。不同型号配置独立维护颜色，不用自由文本替代正式标准目录。固定方式清除比例/基数，比例方式清除固定金额/上限；百亿的零售专属字段为 null。

## 6. 路由、请求与业务操作

### 路由和权限

- 申请人表单、我的提交建立明确路由。管理员「商品」折叠菜单包含源商品库、商品清洗与识别和静态预览商品中心，默认进入源商品库。菜单引用路由名称，路由元信息声明页面准入，菜单不能充当全部路由规则。
- query 按白名单解析类型、枚举和默认值，监听同路径参数变化。仅放允许分享的筛选条件、页码、记录 ID，不放凭证、敏感信息或未保存表单。详情 ID 存在性与访问权仍由服务端核验。
- 前端不能从 query、localStorage 或组件开关获得管理员角色。会话过期统一进入登录状态，保护未提交内容的处理不得绕过用户隔离或泄露数据。
- 客户端免登、浏览器扫码和网页授权遵循鉴权文档。`useAuthSession` 维护唯一会话，`useFeishuQrLogin` 管理二维码加载、刷新与释放。普通浏览器只在用户选择扫码时加载二维码 SDK。授权失败时重新发起，用户 token 由服务端处理。[飞书鉴权](feishu-auth-flow.md)

### 请求与列表

- 所有业务 API 通过 `api/request.js`。统一保留 HTTP status、稳定业务 code 和安全提示，区分网络、超时、主动取消、响应解析和业务失败。错误响应非 JSON 或为空时也不能丢失原 HTTP 状态。
- 支持调用方 AbortSignal，组合内部超时与调用方取消，结束后清理定时器/监听器；主动取消不显示“服务异常”。由页面决定业务提示，避免请求层和页面重复通知。
- 首次会话探测的 401 表示未登录；业务请求 401 触发统一会话失效；403 解释无权限；409 保留编辑内容并提示刷新核对，不静默覆盖。
- 列表区分 loading、error、empty、success；新查询取消旧请求或丢弃过期响应，卸载后不继续更新页面。筛选/页容量变化重置或校正页码，筛选字段明确，不用 Object.values 全对象拼接充当正式搜索契约。
- 政策、来源商品和日志接入后使用服务端分页与筛选，不加载全库到浏览器。总数、状态计数以相应接口定义为准。

### 写操作与真实结果

- 保存、提交、审核、任务控制期间防重复，携带服务端要求的版本；创建/提交结果不明时不盲重试 POST，按接口幂等方案或查询结果处理。
- 保存与提交若是独立接口，明确先保存再提交的顺序；不能让用户以为 submit 会自动包含未保存编辑。成功提示只在对应真实响应成功后出现。
- 演示模式显式启用并持续可识别，数据放 mocks/fixtures，经明确入口提供。正式 API 失败不能回退为演示成功。
- 正式详情组件不合成审核历史、同步结果或覆盖结论。演示历史也应在 fixture 中明确给出；缺真实历史显示空状态/错误，审核通过不等于当前生效。
- 本地暂存文件与服务端附件分清状态及标识。附件存储、权限、类型大小和链接规则确认前不直接启用现有上传流程；当前代码中的 20MB/10 个等限制不能被描述为已确认的最终业务约束。

## 7. 样式、响应式与可访问性

- 样式归属、生产构建本地预览和响应式验收矩阵见[前端工程检查与验收](frontend-harness.md)。
- 品牌色、文字色、间距、圆角等少量公共变量集中维护；基础样式全局加载，布局/页面样式就近引入。不能只是把一个大文件机械切成几份。
- Element Plus 优先通过变量调整；覆盖选择器带业务根类，禁止裸 `.el-button svg`、`.el-upload-dragger` 等影响其他页面。使用内部结构选择器和 !important 时说明必要性及作用范围。
- Teleport 弹层通过专用 popper-class 限定必要的全局样式，不能为了 scoped 破坏日期或下拉弹层适配。
- 用函数调用 Element Plus 的 `ElMessageBox` 或 `ElMessage` 时，在调用模块显式引入相应的 `style/css`。验收时直接打开对应路由，确认弹框和提示在首次加载后显示正常。
- 修改布局按影响范围检查 1440、768、390px：日期完整到秒、弹层边界及纵向滚动、表格容器横向查看、固定操作列、分页换行、确认取消回显。
- 可点击控件有可理解名称、键盘焦点和操作反馈，表单有标签及错误提示。对现有较小字号集中评估可读性；静态审查不等于已测量对比度或可访问性合规。

- 规格变化清空颜色、目录停用、三种颜色范围状态；共享补贴不复制数量。
- 金额 0.10、空数量、0、布尔 false 和时间经适配后语义不变；草稿/正式提交差异与补贴互斥。
- 401/403/409、非 JSON 响应、主动取消、旧响应晚到、写请求结果不明。

- 历史缺失不造记录，演示与正式模式隔离，失败不显示成功。
