## 执行期和收件规则

| 事件 | 登记与发送口径 |
| --- | --- |
| 开始执行 | 采购批准当秒已经采用的范围并入终审群结果。未来开始的政策到起点按商品与平台回放，百亿沿用平台与配置规则。迟到投递同时核对起点和当前采用情况。只在旧单被采用的范围不报新单生效。群中点名相应平台现负责人。 |
| 临期与截止 | 以北京时间实际截止为准。普通原单使用业务到期日末秒，延期段保留精确截止秒。临期档位从截止前 3 天起至截止秒，截止事件从次秒起。临期消息提供「打开我的提交」，调整按钮沿用登录人对该单的服务端权限。点名原申请人及受影响现负责人，按人去重。原申请人停用时，有有效接手人仍可送达，管理端显示无法点名的账号。 |
| 切换与补送 | 启用或重启扫描当前仍有效及未来已批的政策，包括随单获批的延期子单。首次启用跳过此前已结束的政策。已经登记的投递在服务恢复后重新核对时窗。原单、轮次、实际截止、档位和目标群共同防重。 |
| 截止变更 | 在终审成功事务内按受影响目标登记。缩短原单时作废旧档位，以核准的实际截止建新计划。拟定截止已经过去时取批准前一秒。群通知发起人、原申请人和受影响现负责人。随单多目标随批准事务一起提交或回滚。 |
| 延期 | 延期待审和退回均保持原日程。截止通知区分自然结束、提前结束、另有延期仍待审或延期已批准。获批延期单独安排后续提醒，接续起点取原截止次秒和实际批准时刻中较晚者。晚批消息注明空档。 |
| 平台交接 | 平台分工保存成功后，按渠道和平台登记。现有页面先释放再分配，释放时通知待分配，接任时注明前后负责人。停用或升为管理员引起的释放也登记。相同分工重复保存不新增提醒。退回修改仍归原申请人。 |
| 商品批次 | 本批导入或清洗的发起管理员负责处理。导入异常暂停按批次及暂停版本登记，已续跑的旧暂停失效。清洗结束时汇总本批待人工审核、技术失败两项数量。只有自动排除和正常结果时没有提醒。发送前复核该企业有效管理员身份，无法解析时保留失败记录供管理员核对。 |

管理员从「政策审核设置 → 飞书投递记录 → 查询业务提醒」按登记顺序查看延期、临期、交接和商品批次。每页最多 50 项。可核对下次可投递时间、实际飞书回执、失效或失败原因，单独补发或补录经核实的未知回执。审核卡和个人待办按政策单号与轮次查询。[投递接口](../api/policy-review-settings.md)

### 群消息与投递编号

后端重启加载新版后，新群消息显示业务摘要，并按需 @ 收件人、附办理链接。投递编号移出消息正文，管理员可在「政策审核设置 → 飞书投递记录」查看。发送请求继续携带同一个 UUID 防重。此次正文调整无需改表，已有群消息上的编号仍可用于核对历史回执。[投递记录与人工核对](../api/policy-review-settings.md#飞书投递记录与人工核对)

## P33 切换、暂停与恢复

1. **升级前**，停写并备份目标库和附件，确认目标库已具备 E 阶段卡片约束。已有库先运行 F 增量，再运行核对 SQL。空库使用完整基线的任一份。SQL 执行及差异核对由用户在 Navicat 完成。[数据库说明](../sql/database-design.md#已有库升级执行期与业务提醒)
2. **部署前**，分别核对测试和正式的企业、应用、业务群、ERP 根地址、来源白名单、服务器北京时间与手机可达性。管理员在 ERP 核对运营和采购两组名单、在途轮次指派、自审排除及可改派人。确认机器人在群内，具备发送、读取消息、验证群成员及 Task V2 所需权限。按部署模式核对长连接或 HTTP 卡片回调。[部署参数](environment-configuration.md) · [卡片回调及权限](policy-workflow-phase-e.md#环境配置与目标库)
3. **启用**，先完成现场联验并留存目标 MySQL 核对结果。将使用同一队列的实例部署为同一版本，设置 `POLICY_REVIEW_DELIVERY_ENABLED=true` 后重启。默认每 3000 毫秒领取一项到期动作。检查近期业务提醒、最长待发时间、已失效项、失败和结果未知项，再对照飞书回执。首次补送覆盖当前临期窗口。
4. **暂停**，在所有投递实例关闭上述开关并重启，核对停机前已经发出的请求。保持 ERP 和卡片回调在线。已发卡仍可签署，原流程的按轮指派继续决定采购权限。新建卡、卡面更新、结果群通知和待办在队列等待。已登记原单的截止调整仍更新原计划。
5. **恢复**，核对企业、目标群、原群回执、当前轮次和成员，在同版本实例恢复开关。已有回执继续保留，旧指派和过时提醒在发送前再核验。对显示「结果待核对」的项先查询飞书原记录，确认送达则补录可信回执，确认未送达才重新入队。逐项填写核对依据。
6. **应用版本回退**，优先暂停外发。需回退至 E 版时先停止 F 版实例，保留扩展后的表结构、所有登记和回执，并在旧版保持自动投递关闭。旧版执行器仅认识审核轮次。重新部署 F 版后核对暂停期间的政策、分工和批次变化及仍在办的指派，再决定恢复范围。完整现场闭环和目标库核对完成后方可登记正式切换。
