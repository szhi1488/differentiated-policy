# 管理员工作台

管理员与申请人共用顶部导航栏：左侧开关收起或展开侧栏，当前位置随路由变化，右侧可搜索当前角色已有菜单、查看帮助和登录人信息。菜单搜索不查业务数据、不扩展权限。桌面收起侧栏后主区扩展，手机使用临时菜单与遮罩，选择页面、按 Esc 或点击遮罩后关闭。头像来自服务端 `user.avatarUrl`，缺失或加载失败使用姓名首字。没有接入站内通知或个人设置，不显示无实际功能的入口。

侧栏与申请人共用 `workspace-navigation.css`：品牌间距、蓝色分组、图标、子菜单缩进、字体、浅蓝选中态和箭头一致。桌面 196px，平板 160px，手机抽屉 196px；角色菜单与路由仍各自维护。

侧栏底部使用两角色共用的波浪背景；各管理员页面的标题横幅统一为波浪图、104px 基准高度、桌面 22px／手机 20px 标题和同一风格的 SVG 线性图标，标题下不显示说明小字。顶部导航下的主内容区使用单独的浅蓝波浪图，短页铺满剩余屏幕、长页随内容延伸。申请人提交政策、我的提交同步使用共用标题和背景规则。详细资源、边缘裁切与响应式间距见[两角色工作台视觉](frontend-development.md#两角色工作台视觉)。

更新日期：2026-11-17。

管理员登录后进入 `#/admin/catalog/sources`。点击左侧「商品」可展开或收起「源商品库」「商品清洗与识别」和「商品中心」。进入任一子页面时，分组自动展开并高亮当前页面。旧管理员地址由路由守卫统一跳回源商品库。申请人访问管理员地址时回到 `#/apply`。客户端免登、浏览器扫码及网页授权都按服务端会话的 `user.roleType` 分流。[飞书鉴权](feishu-auth-flow.md)

## 用户管理

管理员从「系统管理 → 用户管理」进入 `#/admin/users`。页面使用本公司用户接口，当前账号按登录会话的本地 ID 标记。系统管理位于管理员侧栏顶部，默认登录入口为源商品库。

- 首页分别读取列表和全公司统计。姓名或部门关键词、角色、启停状态在回车或点击「查询」后生效，只影响列表。重置或更改页容量回到第一页，每页支持 10、20、50 条。没有匹配结果时可重置筛选。
- 「查看」按本地 ID 读取最新详情，展示头像、姓名、部门、加入时间、角色、状态及可复制的飞书 openId。部门为空显示「—」，账号移出列表筛选范围时仍可查看其详情。
- 调整角色、启用或停用前，确认弹窗独立读取目标详情并显示当前角色和状态。管理员确认后，页面携带这次读取的旧值写入。取消不提交，写入期间防止重复确认。本人账号的两个修改入口禁用，最终权限及最后一位有效管理员保护由后端核验。
- 写入成功后重新查询已提交筛选条件下的当前页、独立全量统计和已打开的详情。若末页已空，自动回到最后一个有效页。手动刷新同样从服务端读取。
- 调整角色后，目标账号重新打开、刷新或切回应用时按最新角色进入工作台。升为管理员后，从旧申请地址进入「商品 → 源商品库」；降为申请人后，从旧管理地址进入「政策提交 → 提交政策」。[本地复测步骤](feishu-auth-flow.md#角色调整后重新进入工作台)
- 409 或写入结果未知时，弹窗保留所选目标并显示实际错误，重新读取账号供核对。结果已经符合目标时禁止重复提交。各区域读取失败可独立重试。[用户接口](../api/user-api.md)

桌面显示四列统计卡，平板和手机使用两列。窄屏表格在容器内横向滚动，详情抽屉与确认弹窗适配可用宽度。

## 机型补贴查询（静态预览）

从「政策管理 → 机型补贴查询」进入 `#/admin/model-subsidies`。本轮仅供确认页面效果，页面明确标注「静态预览 · 示例数据」。管理员默认入口仍为源商品库，申请人路由及菜单不变；新页面沿用管理员角色路由守卫及共用顶部栏的菜单搜索。

上方使用 Element Plus 筛选品牌、机型版本、配置及日期范围，点「查询」应用到内置示例。下面共用同一组选品条件，上下展示「零售补贴时间轴」和「百亿补贴时间轴」：每个平台一条独立横向轨道，固定补贴为蓝色、比例补贴为橙色，色块显示方式、参数和日期。底部滑块缩放时间；悬停查看参数，点击色块后右侧展示政策单号、完整补贴参数、适用时间及实际商品。两张图仅保留标题和图例，不显示副标题及平台数量；补贴明细直接展示内容，不显示点击提示或下拉选择框，仍可通过时间轴色块及所选时点补贴按钮切换明细。勾选「展开独立商品」后显示独立商品轨道，仍与同色的配置商品区分；示例参考数量 0 保留展示。

时间轴按页面读取的北京时间，为示例中正在适用的区间显示绿色「当前适用」标记，结束日期不再用查询截止日期冒充政策到期。仅在可视时间窗口包含当前时点时显示当前标记。比例色块直接显示百分比及计算基数，较窄色块按两行显示；完整参数仍可悬停或点击查看。

悬停只强调边框，蓝色、橙色底色保持稳定，移开后恢复普通边框；点击选中的色块保留选中边框。指针移动复用同一份分渠道数据，不重建图表，切换选中项前清理上一轮悬停。页面按用户要求移除时间指针下方的联动范围说明、两张图底部的操作及时区说明、页尾展示口径说明；上方静态示例标识继续保留。

两图共用一条时间指针和缩放范围。在任一图移动鼠标或拖动蓝色指针，两图同步定位到精确到秒的北京时间；右侧「所选时点补贴」按已有示例区间列出该时点各平台的补贴，可点击查看对应明细。任一图的底部滑块调整后，另一图同步缩放，静默回写避免循环；最小显示范围为总区间的 5%。指针超出缩放窗口时移到最近边界。按用户要求移除机型配置摘要及独立的时间指针操作栏，查询区控件缩短并按宽度换行，「展开独立商品」移至查询操作旁。点击「当前时间」读取此刻北京时间，将查询结束日期带到今天；起始日期在未来或未填时改为今天，否则保留起始日期，同时应用当前选择的机型配置、恢复完整缩放并让两图指针及右侧时点结果定位此刻。查询和重置也刷新当前时间。时间来自浏览器时钟，政策仍是静态示例，不代表真实业务结果。更换查询条件时恢复完整缩放和范围末端指针。按用户要求移除右侧「补贴方式说明」卡片。

`AdminModelSubsidiesPage.vue` 组织页面，`PolicySubsidyTimeline.vue` 提供两张时间轴。ECharts 6.1.0 仅注册自定义图、坐标轴、提示、缩放和 SVG 渲染模块，随新路由按需加载，卸载时销毁实例和尺寸监听。示例数据集中在 `src/mocks/fixtures/model-subsidies.js`，使用预设历史节点和开放结束区间展示到当前查询时点，不作为正式接口的异常回退。

页面图标使用 SVG：管理员侧栏品牌标识、标题、图例、查询、提示和独立商品勾选标记复用 `AppIcon.vue`，日期与下拉图标沿用 Element Plus 的 SVG。时间轴的平台名称旁增加本地 SVG 简称标识，平台标识与对应轨道使用同一组行数据，独立商品展开后同步对齐。图表继续使用 ECharts SVGRenderer，不使用位图或字体图标。

页面不读取商品、政策或审核接口，不在前端重建真实覆盖算法，没有新增后端接口或数据库调整，也未接入申请人页面。真实已通过政策查询、历史区间计算、快照明细及权限校验均待后续业务接入。模拟会话与三个尺寸的生产预览见[初版记录](frontend-development.md#2026-11-16-机型补贴查询静态预览)、[悬停修复](frontend-development.md#2026-11-16-时间轴悬停恢复与说明移除)、[内容精简](frontend-development.md#2026-11-16-机型补贴页面内容精简)及[当前时间定位](frontend-development.md#2026-11-16-紧凑查询区与当前时间定位)；初版的固定示例时点和旧操作入口仅作为历史验证记录，当前行为以本节及最新记录为准。

## 差异化政策

从「政策管理 → 差异化政策」进入 `#/admin/policies`。申请单号统一显示 `ZC-000005` 这类短编号，支持关键词查询，驳回重提不变。页面读取本公司已提交的政策，默认显示全部已提交记录，每页 10 条，可切换待审核、已通过、已驳回。按渠道、整单平台、核销类型、涉及场景、提交人、提交日期及关键词筛选。

列表、筛选、状态数量统计和详情摘要均以最近一次正式提交为准。申请被驳回后，申请人将拼多多改为淘宝并仅保存时，管理员仍看到拼多多，也仍按拼多多命中筛选；重提成功后才更新为淘宝。渠道、核销类型和场景遵循同一规则；申请人编辑页继续回填自己已保存的新内容。

筛选区域使用浅色分区和上方标签，控件统一为 Element Plus 默认 32 像素高度。桌面第一行放渠道、平台、核销类型和涉及场景，第二行放关键词、提交人、提交日期和右侧查询操作；平板和手机自动换行，日期范围保持完整。选中或输入条件后按回车或点「查询」提交，「重置」清空条件并刷新，不改变现有查询契约。

「查看」和「审核」共用同尺寸的模态窗口，桌面最大 1280 × 732 像素，窄屏按区块纵向排列并在窗口内滚动。详情展示当前提交轮次的快照、补贴、备注、附件链接和审核意见。待审核详情逐平台和商品显示覆盖预览，已通过详情显示当前生效范围，可点单号查看适用政策。[审核接口](../api/admin-api.md)

覆盖区顶部按「商品 × 平台」汇总结果项数，点击类别可筛选，支持叠加平台、商品关键词条件，每页 10 组。每行显示本申请补贴；「对比补贴」在独立只读弹窗并列显示本申请与命中轮次的原补贴，提示固定金额、上限或同基数比例的变化。点击对照政策单号可直接展开该轮完整内容及附件。通过「返回原申请」、关闭按钮或 Esc 返回，保留原审核目标、筛选、分页、滚动位置和已填驳回原因。覆盖算法与最终审核版本校验不变。[对照规则](../business/override-engine.md#4-管理员覆盖预览与补贴对照)

普通选品的覆盖结果先按机型版本、配置和平台汇总；同组商品结果不一致时显示「部分覆盖」及各结果数量，不因补贴和对照轮次差异拆行。展开后查看每件商品的颜色、ID、名称、覆盖结果、本申请补贴及各自对照入口；整组结果与新旧补贴、对照轮次一致时仍可直接整组对照。指定卡保持单品，型号配置缺失或不匹配时保守展示单品。支持按结果、平台、机型、配置、颜色及 ID 筛选，先筛选商品再汇总、每页 10 组，汇总只包含本申请已选且命中筛选的商品。页脚同时标明组数和实际范围项数。对照只取已通过政策，后端仍限定同渠道、同平台及同商品判断覆盖。

覆盖区采用企业应用表格布局：顶部并列展示标题、同渠道同平台提示及生效时间；下方浅色工具区上排为结果筛选按钮，下排为带标签的平台、商品关键词及重置操作。主表按「型号及配置、平台、适用结果、本申请补贴、政策及补贴对照」排列，型号下方显示已选颜色和商品数量，不再单独占一列。统一结果只显示一次状态，混合结果显示「部分覆盖」及分项数量；展开明细使用独立浅色区域。说明文字移到表尾，窄屏控件自动换行，表格在容器中横向滚动。此布局限定覆盖预览及生效范围区，沿用查看、审核和批准前复核中的同一组件。[实现与验证](frontend-development.md#2026-11-16-覆盖区型号配置总览与布局)

窗口提供「当前申请」「审核记录」页签。进入「审核记录」才读取历轮列表，每页 10 条，按轮次倒序展示提交时间、审核结果、审核人、审核时间和意见；已通过的空意见显示「—」，已驳回但未填意见时明确显示「未填写审核意见」。点击「查看内容」读取该轮完整提交快照，包括机型、颜色、平台、数量、补贴、备注及附件，附件按该轮日志 ID 下载。「返回审核记录」保留列表页码。历史内容只读，不显示当前覆盖结果或通过、驳回按钮；返回「当前申请」后可继续本轮审核。列表与单轮读取失败分别提供重试，关闭窗口、切换页签或申请后丢弃迟到响应。前后轮次的修改对比尚未实现。

桌面详情右侧「其他信息」使用 280 像素宽的浅色栏，备注和附件采用上方标签、下方内容的排版。附件及链接逐项排列并显示总项数，长名称完整换行；备注和审核意见保留原有换行。审核信息通过分隔线单独分组，审核人和审核时间分别展示，未审核时不显示空的审核区块。平板和窄屏随详情区块纵向排列。

仅在服务端返回 `reviewable` 时显示「审核」。审核窗口底部提供「通过」和「驳回」。点击「通过」打开「确认审核通过」窗口并重新读取详情，读取中禁止确认；核对当前版本及覆盖结果后，列出整份申请的渠道、实际适用平台、商品数及覆盖汇总，筛选和分页不缩小批准范围。结果变化时展开最新覆盖预览，须勾选「我已核对最新覆盖结果」后才能点击「确认通过」。核对失败可重试，申请状态、记录版本、提交轮次或审核权限变化时须重新读取原政策。取消保留原窗口的筛选、分页及驳回原因。

点击「驳回」打开原因小窗，意见选填，最多 512 字。取消或按 Esc 返回审核窗口，同一次审核中重新打开会保留已填内容。「确认通过」和「确认驳回」提交当前记录版本及提交轮次，写入中禁止重复操作。成功后刷新列表和详情，版本冲突或结果未知时提示重新读取。[审核接口](../api/admin-api.md#审核)

审核通过无需填写意见。已通过详情在意见为空时只展示审核人和时间，不显示「审核意见」及缺失提示；历史快照和补贴对照窗口沿用相同展示。历史实际保存的非空意见继续按原文展示，驳回原因及其空值提示保留。

「机型及补贴信息」按选品方式展示。每张普通卡按机型版本、RAM、ROM 和补贴方案分行，同行列出共用该方案的适用平台。点击配置下的「查看颜色」展开本轮快照中实际勾选的商品颜色。指定适用机型单独成块，直接显示具体颜色，并按平台各列一行数量与补贴。未填数量显示「未填写」。仅展示有数据的区块。

点击文件名后，页面带当前管理员会话读取指定申请和提交轮次的附件，取得字节后触发保存。下载期间显示状态并防止重复点击，失败信息显示在文件名下。飞书客户端与外部浏览器的登录会话各自独立，文件由当前页面完成鉴权读取。[附件接口](../api/attachment-api.md#已实现接口)

## 源商品库

右上角「导入商品」打开弹窗。选择 OPPO 或一加、全量导入或按建档日期导入。按建档日期时必须选择日期。在品牌页签中打开弹窗会带入当前品牌；有活动任务时优先显示其状态、读取数和去重数。暂停后可继续或结束。同账套每次处理一个导入任务，导入完成后等待管理员发起清洗。

筛选栏左侧为建档日和关键词，右侧为重置和查询。可结合品牌页签查看指定建档日的商品，分页保留已应用的筛选条件。弹窗中的建档日任务已有入库结果时，「查看该日商品」会直接应用对应品牌与日期。建档日取自按日导入命中，缺少确认记录时显示「—」。

表格分别显示 `gmtModified` 对应的 SKU 修改时间和 `goodsGmtModified` 对应的商品修改时间，均为北京时间，非零毫秒保留三位。分页栏的「前往」可输入页码后按回车跳页。窄屏可打开侧栏，表格在自身容器内横向滚动。

布局由 `frontend/src/layouts/AdminLayout.vue` 提供，页面为 `frontend/src/views/admin/catalog/CatalogSourcesPage.vue`。任务轮询和列表状态由 `useSourceGoods` 管理。后端接口和配置见[商品管理接口](../api/catalog-api.md)与[项目 README](../../README.md#吉客云商品导入)。

## 商品清洗与识别

清洗页 `#/admin/catalog/cleaning` 默认汇总 OPPO 和一加的当前来源商品。品牌、建档日期和商品名称或货号用于筛选。建档日期可选不限、指定一天或建档日未知。页签显示同一筛选范围内的全部、待清洗、待人工审核、已通过、技术失败和已排除。已通过包含自动和人工通过。

右上角「开始清洗」打开商品预览。选择品牌和指定建档日期，或选「该品牌全部已入库商品」纳入建档日未知的 SKU。预览按 SKU 分页，显示商品名称、货号、SKU 名称、建档日期、已识别机型和状态。关键词只筛选预览表。预计数量默认统计导入已完成或已结束的待清洗 SKU，可同时重新识别未建立映射的待审商品。二次确认框居中展示范围和数量，「返回预览」保留已选范围。任务受理后显示进度。「清洗记录」显示每轮通过、待审、失败和跳过的数量。

来源详情显示原文、识别证据、当前商品映射和最近人工审核结果。「来源原文」在「分类名称」下显示完整分类路径 `cateFullName`，缺值显示「—」。待审商品保留系列、型号、配置和颜色四个填写框，底部直接点「审核通过」或「审核不通过」，无需填写原因。通过须填齐四项，命中排除规则时禁用「审核通过」。不通过后进入「已排除」，服务端自动保存审核结果。窄屏时弹窗内容可滚动，底部按钮保持可见。状态冲突保留填写内容，重新读取候选后可提交。技术失败可从列表逐条重试。[商品管理接口](../api/catalog-api.md) · [清洗细则](../business/catalog-cleaning.md)

## 商品中心

页面风格与差异化政策、机型补贴查询统一：蓝色主按钮及选中态，白色卡片、浅色筛选背景、轻边框和阴影；商品销售状态保留语义色。原有统计、分类、筛选和表格的排版、尺寸及操作保持不变。[风格对齐与验证](frontend-development.md#2026-11-16-商品中心风格对齐)

从「商品 → 商品中心」进入 `#/admin/catalog/center`。统计、品牌／系列／机型分类、筛选、分页和详情读取公司标准目录。点系列展开机型并查看该系列，点机型筛选对应机型版本。分类搜索支持机型名称，「仅看在售商品」同步更新各级计数。品牌、商品状态、系列和配置下拉选中即刷新列表并回到第一页。切换品牌会清除不匹配的系列及机型。关键词可按回车或点「查询」，点清除立即刷新。输入部分机型、商品名、货号或 SKU 即可查询，也可用空格组合不同字段，如「Ace7 黑色」。列表读取失败时可用原条件重试。「商品信息」上方显示源商品的吉客云 SKU ID，下方显示标准商品货号，字段为空时显示「—」，有货号时可点击复制图标。每条通过的源 SKU 独立对应一条商品，`goods.sku_id` 保存该来源原始 SKU；同规格同颜色的不同 SKU 分行显示。销售状态为空时显示「未知」。详情的来源名称取同一条来源的吉客云 `goodsName`。列表、详情和配置筛选项将 1024GB 存储显示为 1T。列表支持按更新时间排序，「更多操作」可导出当前页。[商品管理接口](../api/catalog-api.md)

勾选商品后，筛选栏的「导出」下载已选商品的 CSV，包含翻页后仍保留的勾选。查询、重置或切换筛选条件会清空勾选。CSV 与「导出当前页」使用相同字段，含来源 SKU。

可下载 CSV 导入模板，列顺序为货号、商品名称、品牌、系列、机型、配置、颜色、版本。标准商品批量导入入口待接入。新增商品通过右侧抽屉保存，分别填写 RAM、ROM，ROM 可填 1T。普通机型可留空版本，销售状态默认「待上架」。手工新增商品的 `skuId`、来源 SKU 和货号均为空。每行「删除」须确认，成功后从标准商品表永久移除该记录，刷新默认列表、分类和统计。已关联吉客云来源 SKU 或被政策引用（含商品所在配置）时，页面提示原因并保留记录。数据字典读取真实品牌、系列和颜色，支持新增及未引用条目的改名和删除。系列下仍有商品或政策引用时锁定编辑和删除。只剩无引用机型时可改名，确认删除系列后同时清理这些机型。删除商品成功后刷新字典引用状态。商品抽屉读取同一套字典选项。

点击「编辑」读取最新详情，可修改商品名称、系列、机型、RAM、ROM、颜色、版本和销售状态。名称输入框回填标准目录中保存的商品名称，ROM 输入框将 1024GB 回填为 1T。已有销售状态为空的商品可保留「未知」。品牌可在商品尚未关联来源时修改。政策明细引用具体商品时，该商品的机型版本、容量和颜色受保护。现有引用检查也会保护被旧政策明细引用的整个配置。接入新政策三表后改按实际选中的商品 ID 检查，机型和系列维护检查明细引用的机型。

保存后按当前筛选刷新列表、分类与统计，可从「查看」核对结果。遇到重复规格、并发修改或其他保存失败时，抽屉显示原因并保留输入。取消编辑时可选择继续编辑或放弃修改。[商品编辑接口](../api/catalog-api.md#商品编辑)
