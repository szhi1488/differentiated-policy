# 前端工程检查与验收

适用于 `frontend/` 的页面、样式、测试和构建变更。业务规则、数据流和鉴权约定见[前端架构与开发规范](frontend-development.md)。

## 目录与样式归属

| 位置                                                    | 内容                                                                                                                                              | 检查方法                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `frontend/`                                             | 应用入口 HTML、构建与检查配置、依赖清单和锁文件                                                                                                   | 顶层保持为工程入口，新增产品代码放入 `src/`                                                          |
| `src/assets/styles/`                                    | `base.css` 提供基础样式与全局变量，`brand.css` 提供跨工作台品牌样式                                                                               | 从 `src/main.js` 引入，检查新增选择器是否真的跨页面复用                                              |
| `src/layouts/`                                          | 工作台导航与页面出口。`workspace-navigation.css` 共用侧栏视觉，`admin-layout.css` 和 `applicant-layout.css` 分别维护布局；`WorkspaceTopbar.vue` 就近维护顶部栏样式 | 由对应布局加载，布局专属组件放 `layouts/components/` |
| `src/views/`                                            | 路由页、业务子组件与跨组件业务样式，例如 `policy-form.css`、`catalog.css`                                                                         | 单组件规则优先写在 Vue 文件的 `<style scoped>`，共享规则以业务根类约束，由所有使用方所在模块明确引入 |
| `tests/`、`scripts/`                                    | Vitest 测试和本地验收入口                                                                                                                         | 产品入口只依赖 `src/`。测试路径、mock 与配置随文件迁移同步更新                                       |
| `dist/`、`node_modules/`、`.local-cache/`、`.research/` | 构建输出、安装依赖和本地临时资料                                                                                                                  | Git 已忽略。修改样式在源码完成，再重新构建生成哈希文件                                               |

新增 Element Plus 覆盖时优先使用组件变量或业务根类。涉及组件内部节点时限制选择器范围。Teleport 弹层使用专用 `popper-class`，例如申请表单的 `policy-date-popper`。路由页面的基础及断点样式要能在首次直达时加载，避免依赖此前进入其他页面留下的样式。样式迁移同时验证直达与来回切换。

## 用户管理专项验收

使用管理员会话直达 `#/admin/users`，在 1440×1000、768×1000 和 390×844 检查表格、详情抽屉及操作弹窗的边界。通过隔离账号验证角色调整、停用及启用，检查成功后列表、全公司统计及已打开的详情同时更新，离开并返回后可读到已保存的数据。申请人直达本页须回到申请页。

检查组合筛选、分页、重置和末页回退，列表筛选不应影响统计。用最新详情构造写请求，核对本人按钮、取消及重复提交保护、409 时保留所选目标、结果未知时重新读取、独立错误重试以及关闭后忽略迟到响应。目标 MySQL 和真实飞书会话另行验收。[用户接口](../api/user-api.md)

## 自动化检查

在 `frontend/` 运行。安装依赖使用锁文件和项目约定的 `npm.cmd ci`。

```powershell
npm.cmd run check
```

| 步骤          | 覆盖内容                                                                                                                                                                                               | 失败处理                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| ESLint        | JS/Vue 基础规则、props 写入、运行环境和部分依赖边界。浏览器源码与测试使用浏览器全局变量，工程配置与脚本使用 Node 环境。核心逻辑层静态导入页面或布局，以及 `src/` 下的 `*.test.js` / `*.spec.js` 会报错 | 修正文件归属或依赖方向。涉及浏览器代码和 Node 脚本时分别核对运行环境                                                                 |
| Prettier      | 检查已纳入项目的源码、测试和配置格式                                                                                                                                                                   | 优先对修改文件格式化，检查实际差异                                                                                                   |
| Vitest        | 发现 `tests/**/*.test.js`，执行单元、组件与集成测试。组件和路由联动使用 jsdom                                                                                                                          | 测试迁移前后核对发现数量及通过数量。可用 `npm.cmd test -- tests/integration/router.test.js` 单独排查路由或冷启动超时                 |
| Vite 生产构建 | 从 `index.html` 生成 `dist/`，检查模块解析、样式提取和异步路由分块                                                                                                                                     | 构建入口或依赖变动时比较入口与相关异步块的原始和 gzip 体积。检查布局、路由和 Element Plus 组件仍按需加载，记录新增依赖或显著增长原因 |

Windows 下若 esbuild 在加载 Vite 配置时报目录拒绝访问，记录实际错误，用已获准的本机执行环境复查。若测试本身超时，先确认是哪个场景及是否可重现，保留失败记录和重跑结果。`npm.cmd run check` 是现行本地检查入口，浏览器验收按变更范围单独执行。

## 生产构建的本地浏览器验收

先执行 `npm.cmd run build`，再按要验证的场景在各自终端启动预览。预览服务仅监听本机，直接使用 `dist/`。QA 脚本提供模拟会话及访客所需的配置响应，其余 `/api` 返回 501。

| 命令                                  | 入口                                     | 适用场景                                    |
| ------------------------------------- | ---------------------------------------- | ------------------------------------------- |
| `npm.cmd run preview:qa -- GUEST`     | `http://127.0.0.1:4176/`                 | 登录页首屏、品牌、按钮和状态提示            |
| `npm.cmd run preview:qa -- APPLICANT` | `http://127.0.0.1:4174/#/apply`          | 申请工作台、表单、日期、附件展示和菜单往返  |
| `npm.cmd run preview:qa -- ADMIN`     | `http://127.0.0.1:4175/#/admin/catalog/sources` | 管理员默认入口、直达及旧链接回退 |

用浏览器响应式工具核对 1440×1000、768×1000 和 390×844。重新构建后刷新页面。验收结束可在对应终端按 `Ctrl+C` 退出预览。

## 已识别的后续工作

管理员批准确认验收：点击「通过」须先重新读取详情，点击「确认通过」才写入；汇总使用整份申请范围，与覆盖区筛选、分页无关。覆盖结果、对照轮次或旧补贴变化时展开最新预览并要求勾选已核对；仅时间推进、顺序或金额尾零不同不提示变化。核对取消保留原上下文，读取失败可重试，版本/状态/权限变化阻止批准，写入冲突或结果未知须重新读取。核对中取消、关闭和切换时忽略旧响应，写入中禁止重复操作；三个尺寸下确认窗口可滚动、底部按钮可见。

配置汇总验收：三个普通颜色各适用两个平台，加一个其他配置商品适用两个平台时，8 项范围应显示 4 组。改变个别颜色的原补贴、上限或对照轮次后仍为 4 组，改成混合结果时该组显示「部分覆盖」与各结果数量；另一平台保持独立。展开核对全部已选商品 ID、颜色、各自结果及补贴，逐项对照须发送该商品自己的平台与命中轮次。整组补贴或对照不一致时只能逐项打开，不能以首件商品代表整组。指定卡始终保留单品，缺少规格证据不汇总。颜色搜索只显示命中商品，数量和结果随筛选范围变化；同色多 SKU 不丢 ID，缺少旧补贴不阻止型号配置汇总。分页按组、汇总按商品平台范围；桌面、平板和手机下外层及展开明细表均在容器内滚动。

覆盖区布局验收：仅检查覆盖预览及生效范围区域。待审覆盖区顶部只显示标题，已通过时核对生效条件满足时间。结果按钮、带标签的筛选控件和汇总表应层次清晰；已选颜色与商品数量位于型号配置下方，统一结果不重复显示商品计数，部分覆盖显示分项计数。展开明细须保留逐件结果与各自对照入口。1440×1000、768×1000、390×844 下控件正常换行，页面无横向溢出；对照返回后保持原审核目标、筛选及展开内容。多个覆盖组件同时存在时，表单控件 ID 应各自唯一。

覆盖预览验收：核对按商品平台范围汇总、结果/平台/关键词组合筛选、筛选后回第一页、空结果及总数口径。分别打开「对比补贴」和对照政策单号，核对固定金额、空上限与 0、比例百分点、方式或基数变化、命中轮次及该轮附件。填写驳回原因后取消小窗，进入对照并返回，确认筛选、页码、滚动位置、原审核目标及原因均保留；错误重试、关闭与切换时的迟到响应不得影响原审核。对照窗口无审核按钮，手机表格内部滚动、对照内容纵向排列且返回按钮可达。

管理员审核记录验收：从查看和审核窗口进入「审核记录」，核对轮次倒序及分页、提交与审核时间、驳回原因及空意见。打开旧轮次后核对原机型名称、颜色、补贴、备注和按轮次下载的附件，历史不显示审核按钮或当前覆盖结果；返回列表保留页码，返回当前申请可继续审核。分别验证列表与快照错误重试、切换申请与关闭窗口时的迟到响应，并检查三个尺寸下的容器滚动。

申请人地址与配置回归补充：手动改变 `policyId`、浏览器前进后退及从列表页直达另一份申请时，分别验证确认和取消；Hash 事件不能自动关闭确认框，取消保留原地址、输入和暂存附件。目标申请加载期间不能切回旧地址造成内容错位，读取失败后能重新打开原申请。编辑普通卡取消配置须包含分页外的已有颜色，取消抽屉保留原卡，保存后核对最终商品 ID；重选配置保留手动取消的颜色。实际自动化及生产预览记录见[申请地址切换保护与已有配置移除](frontend-development.md#2026-11-15-申请地址切换保护与已有配置移除)。

源商品库已接入后端。只模拟会话的预览会显示接口不可用提示；导入和列表交互需要隔离模拟 API 或本地测试库。页面及布局的异步加载已有生产构建输出，后续增加依赖时用构建输出实测成本，按真实加载行为决定是否调整分块。
