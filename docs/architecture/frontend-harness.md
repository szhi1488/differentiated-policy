# 前端工程检查与验收

适用于 `frontend/` 的页面、样式、测试和构建变更。业务规则、数据流和鉴权约定见[前端架构与开发规范](frontend-development.md)。

## 目录与样式归属

| 位置                                                    | 内容                                                                                                                                              | 检查方法                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `frontend/`                                             | 应用入口 HTML、构建与检查配置、依赖清单和锁文件                                                                                                   | 顶层保持为工程入口，新增产品代码放入 `src/`                                                          |
| `src/assets/styles/`                                    | `base.css` 提供基础样式与全局变量，`brand.css` 提供跨工作台品牌样式                                                                               | 从 `src/main.js` 引入，检查新增选择器是否真的跨页面复用                                              |
| `src/layouts/`                                          | 工作台导航与页面出口。`admin-layout.css` 和 `applicant-layout.css` 分别维护各自布局 | 由对应布局加载，布局专属组件放 `layouts/components/` |
| `src/views/`                                            | 路由页、业务子组件与跨组件业务样式，例如 `policy-form.css`、`catalog.css`                                                                         | 单组件规则优先写在 Vue 文件的 `<style scoped>`，共享规则以业务根类约束，由所有使用方所在模块明确引入 |
| `tests/`、`scripts/`                                    | Vitest 测试和本地验收入口                                                                                                                         | 产品入口只依赖 `src/`。测试路径、mock 与配置随文件迁移同步更新                                       |
| `dist/`、`node_modules/`、`.local-cache/`、`.research/` | 构建输出、安装依赖和本地临时资料                                                                                                                  | Git 已忽略。修改样式在源码完成，再重新构建生成哈希文件                                               |

新增 Element Plus 覆盖时优先使用组件变量或业务根类。涉及组件内部节点时限制选择器范围。Teleport 弹层使用专用 `popper-class`，例如申请表单的 `policy-date-popper`。路由页面的基础及断点样式要能在首次直达时加载，避免依赖此前进入其他页面留下的样式。样式迁移同时验证直达与来回切换。

## 自动化检查

在 `frontend/` 运行。安装依赖使用锁文件和项目约定的 `npm.cmd ci`。

```powershell
npm.cmd run check
```

| 步骤          | 覆盖内容                                                                                                                                                                                               | 失败处理                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| ESLint        | JS/Vue 基础规则、props 写入、运行环境和部分依赖边界。浏览器源码与测试使用浏览器全局变量，工程配置与脚本使用 Node 环境。核心逻辑层静态导入页面或布局，以及 `src/` 下的 `*.test.js` / `*.spec.js` 会报错 | 修正文件归属或依赖方向。涉及浏览器代码和 Node 脚本时分别核对运行环境                                                                 |
| Prettier      | 检查已纳入项目的源码、测试和配置格式                                                                                                                                                                   | 优先对修改文件格式化，检查实际差异                                                                                                   |
| Vitest        | 发现 `tests/**/*.test.js`，执行单元、组件与集成测试。组件和路由联动使用 jsdom                                                                                                                          | 测试迁移前后核对发现数量及通过数量。可用 `npm.cmd test -- tests/integration/router.test.js` 单独排查路由或冷启动超时                 |
| Vite 生产构建 | 从 `index.html` 生成 `dist/`，检查模块解析、样式提取和异步路由分块                                                                                                                                     | 构建入口或依赖变动时比较入口与相关异步块的原始和 gzip 体积。检查布局、路由和 Element Plus 组件仍按需加载，记录新增依赖或显著增长原因 |

Windows 下若 esbuild 在加载 Vite 配置时报目录拒绝访问，记录实际错误，用已获准的本机执行环境复查。若测试本身超时，先确认是哪个场景及是否可重现，保留失败记录和重跑结果。`npm.cmd run check` 是现行本地检查入口，浏览器验收按变更范围单独执行。

## 生产构建的本地浏览器验收

先执行 `npm.cmd run build`，再按要验证的场景在各自终端启动预览。预览服务仅监听本机，直接使用 `dist/`。QA 脚本提供模拟会话及访客所需的配置响应，其余 `/api` 返回 501。

| 命令                                  | 入口                                     | 适用场景                                    |
| ------------------------------------- | ---------------------------------------- | ------------------------------------------- |
| `npm.cmd run preview:qa -- GUEST`     | `http://127.0.0.1:4176/`                 | 登录页首屏、品牌、按钮和状态提示            |
| `npm.cmd run preview:qa -- APPLICANT` | `http://127.0.0.1:4174/#/apply`          | 申请工作台、表单、日期、附件暂存和菜单往返  |
| `npm.cmd run preview:qa -- ADMIN`     | `http://127.0.0.1:4175/#/admin/catalog/sources` | 管理员默认入口、直达及旧链接回退 |

用浏览器响应式工具核对 1440×1000、768×1000 和 390×844。重新构建后刷新页面。验收结束可在对应终端按 `Ctrl+C` 退出预览。

| 改动范围                 | 浏览器验收                                                                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全局样式、登录与构建入口 | 访客打开首页，检查卡片及扫码、网页授权入口。模拟端内环境检查自动验证和失败重试。使用模拟授权响应核对二维码加载、刷新、回调及会话恢复。真实二维码与手机扫码确认按 [飞书鉴权](feishu-auth-flow.md) 联调 |
| 工作台布局或路由 CSS     | 两种角色各直达受影响页面，检查导航、主区宽度、页面级横向溢出和路由往返。管理员核对默认、直达及旧链接均进入源商品库，窄屏可以打开和关闭导航 |
| 申请表单和组件样式       | 日期值完整显示到秒，窄屏弹层在视口内且内容可滚动。表格在容器内横向滚动，右侧操作列固定。切到“我的提交”再返回，核对机型和金额仍在。触发清空或切换渠道后取消，核对回显               |
| 管理员源商品库     | 检查两个导入按钮、互斥与暂停提示、失败后继续、品牌/关键词筛选、真实接口模型下的七字段表格与分页。无可用后端时用明确的本地模拟 API 验证；表格在容器内横向滚动 |

记录实际运行的命令、测试文件数与用例数、浏览器尺寸、角色、页面和观察结果。扫码验收分别记录模拟回调与会话恢复、真实二维码显示、手机确认后进入工作台的结果。[飞书登录验证记录](feishu-auth-flow.md#验证记录)

## 已识别的后续工作

源商品库已接入后端。只模拟会话的预览会显示接口不可用提示；导入和列表交互需要隔离模拟 API 或本地测试库。页面及布局的异步加载已有生产构建输出，后续增加依赖时用构建输出实测成本，按真实加载行为决定是否调整分块。
